# 小红砂 / 大红砂 推算依据、古籍考证与标注审计（修正版）

> 审计对象：万年历 app 的「红砂日（小红砂）/ 大红砂」标注（数据来自 `core/shensha.js` 的 `isHongSha2`，由 sxwnl 天文引擎驱动；渲染在 `web/js/detail-ui.js`）。
> 审计日期：2026-08（本轮复核）。

## 一、计算依据与古籍考证

### 1.1 小红砂（红砂日，属凶煞）
- **权威依据**：《钦定协纪辨方书》（清乾隆官修，项目神煞推算的基准典籍）、《万全增补玉匣记》。
- **起法（协纪）**：四孟月酉日、四仲月巳日、四季月丑日。即：
  - 孟月（寅/巳/申/亥月，对应正月/四月/七月/十月）→ **酉日**
  - 仲月（卯/午/酉/子月，对应二月/五月/八月/十一月）→ **巳日**
  - 季月（辰/未/戌/丑月，对应三月/六月/九月/十二月）→ **丑日**
- **月建定义（关键）**：一律按**干支历节气月建**（以立春换月，不以农历初一）。协纪、玉匣记、百科均载明"以节气论，不以初一而定"。app 的 `isHongSha2` 用 `monthBranch = ob.Lmonth2`（节气月建），符合此要求。
- **别名**：红砂 / 红沙 / 红煞 / 红砂煞。凶性：百事忌，尤忌嫁娶、动土、出行、安葬。民谣："嫁娶犯红砂，一女嫁三家；出行犯红砂，必定不还家……"
- **流派差异（需知悉）**：另有《象吉通书》《玉匣记》古法"四仲金鸡四孟蛇"（仲月酉、孟月巳），与协纪"孟酉仲巳"相反。协纪本身亦认为红砂"于易理不合，归于伪神煞"，但民间嫁娶日课普遍采用。项目采用**协纪起法**（与现有 `isHongSha2` 一致），符合"以协纪为权威基准"的既有约定。

### 1.2 大红砂（大红沙，属吉神）
- **权威依据**：《万全增补玉匣记》（康熙甲子原刻）、《象吉通书》。
- **起法（玉匣记原版，纯地支）**：
  - 春（寅/卯/辰月，即正/二/三月）→ **戌日、子日**
  - 夏（巳/午/未月，即四/五/六月）→ **辰日、巳日**
  - 秋（申/酉/戌月，即七/八/九月）→ **午日、未日**
  - 冬（亥/子/丑月，即十/冬/腊月）→ **申日、戌日**
- **吉凶**：与小红砂**相反**，属吉神，百事吉（宜嫁娶、动土、开业、出行，不用避煞）。
- **流派差异**：后世有"春戊子"（仅戊子一天）、"逢戊逢子皆大红砂"等流变；另有"黄砂日"旁支。建议采用玉匣记原版纯地支版（每季两日）。
- **关键**：大红砂 / 小红砂 判定规则完全不同、吉凶相反，读黄历须看清标题，不可混读。

## 二、当前 app 标注审计（2026 全年）

**方法**：直接调用 `core/shensha.js` 的 `computeDayFromLunar(公历y, m, d)`——即线上 `server/routes/calendar.js` 实际调用方式（内部自行转农历），以协纪小红砂起法 + 玉匣记大红砂起法为基准逐日核对。

> ⚠️ 过程纠偏说明：首轮探针误将 npm `lunisolar` 的"农历日期"二次喂给"接收公历"的 `computeDayFromLunar`，产生"引擎月支偏 2 位、小红砂几乎全错"的假象。改用公历直接调用后，抽 12 个月中央日核对，引擎 `Lmonth2` 月支与节气月建 **0 偏移、完全一致**，确认首轮为假象，特此更正。

**结果**：

| 项目 | 结论 | 证据 |
|---|---|---|
| **小红砂（凶）** | **标注无误** | 全年 365 天，`dat.hongsha` 与协纪起法 **完全一致（365/365，漏标 0、误标 0）** |
| **大红砂（吉）** | **完全缺失** | `dat` 对象与 `detail-ui.js` 均无任何"大红砂 / dahong"字段或渲染；2026 按玉匣记应标 **62 天** |
