# 代码质量红线规范（万年历项目）

> 本规范是团队技术的"地基"。所有提交都必须满足以下红线；Code Review 以本规范为闸门。
> 每条红线都来自本项目真实踩过的坑，括号里是反面教材。

## 一、核心原则

1. **单一事实源（Single Source of Truth）**：同一逻辑/常量/密钥只在一处定义，别处引用，禁止复制粘贴。
   - 反面：HMAC 密钥、签名算法曾在 `auth.js` / `smoke_test_api.js` / `api.js` 三处各写一遍，改一处忘一处就会前后端验签不一致。
   - 正解：服务端 `server/lib/hmac.js`、浏览器端 `web/js/hmac-spec.js` 为唯一定义，调用方 `import`/`require`。
2. **防御性（Defensive）**：任何"以为成功其实失败"的操作都必须显式校验。
   - 反面：备份命令某行 `cp` 静默未落盘，还原时才发现文件缺失（2026-07-14 紫微撤销事故）。
   - 正解：用 `tools/safe-backup`，cp 后立即校验每个 `.bak` 存在，缺失即报错退出。
3. **可还原（Recoverable）**：改任何文件前先备份；崩了能一键回退。
   - 所有 `Back/` 目录为还原点，禁止手动删改其中的历史快照。

## 二、安全红线

4. **nonce 必须密码学安全**：用 `crypto.randomBytes`(Node) / `crypto.getRandomValues`(浏览器)，**严禁 `Math.random()`**（可预测，等于没防重放）。
   - 反面：`smoke_test_api.js` 曾用 `Math.floor(Math.random()*100000)` 生成 nonce。
5. **密钥集中管理**：HMAC 密钥只在 `server/lib/hmac.js`（服务端权威值，env 可覆盖）与 `web/js/hmac-spec.js`（前端明文，按设计非保密）两处定义，禁止在业务代码里再写一遍字面量。
6. **输入校验**：所有外部输入（header / query / body）先校验再使用；数值用 `parseInt(...,10)` 并判 `isNaN`；字符串判空。

## 三、算法与数值红线

7. **历法/命理数值必须交叉验证**：重要计算结果用≥2 个独立库互相印证（本项目用 lunar-javascript / mystilight / lunisolar 三库 harness），差异必须能解释（流派差异 vs 真 bug）。
   - 反面：八字时柱午夜 bug（`h=0` 被 `||12` 误判为正午）靠交叉验证才抓出。
8. **历法边界必须覆盖**：闰月、跨年、晚子时（23:xx 换日）、节气交界月建，必须有抽样/单测。
9. **禁止重复实现**：相同算法（如 HMAC、时辰映射、干支换算）抽公共模块，禁止在多个文件各写一份。

## 四、前端红线

10. **国风用设计令牌，禁硬编码色值**：所有颜色/字号走 `variables.css` 的 `--color-*` / `--font-*` 令牌；改主题只改令牌，不改散落的 `#xxxxxx`。
11. **错误处理不可吞**：`fetch`/`await` 必须 `.catch`，异常要上抛或降级展示，禁止静默 `catch(e){}` 吞掉。
12. **模块边界清晰**：前端为 ES module（`import`/`export`）；共享规范放 `web/js/*-spec.js`，禁止在业务组件里内联重复常量。

## 五、提交纪律

13. 提交前自查：是否备份？是否 `node --check` 语法通过？跨库数值是否验证？
14. 禁止"顺手改"无关代码；一次提交聚焦一件事，方便回滚与 review。
