# Code Review 清单（合并闸门）

> Reviewer 按本清单逐条核对，**全部通过**方可合并。每条对应《代码质量红线规范》编号。
> 用法：在 PR 描述里逐项勾选；reviewer 复核打勾。

## A. 提交前自检（Author 必做）

- [ ] **A1 备份且落地校验**：改前用 `bash tools/safe-backup <文件...>` 备份，`Back/safe_*` 下每个 `.bak` 都已生成（红线 2、3）
- [ ] **A2 语法检查**：`node --check`（Node 文件 .js / 浏览器模块 .mjs）全部通过，无遗留 `import` 误报
- [ ] **A3 自测**：改动点手动/脚本验证通过，未在无关代码"顺手改"（红线 14）
- [ ] **A4 单一事实源**：没有新增"第二份相同逻辑/常量/密钥"（红线 1、9）

## B. Reviewer 核查（逐条打勾）

### 安全（红线 4、5、6）
- [ ] **B1 nonce 安全**：任何 nonce/随机令牌用 `crypto.randomBytes` / `crypto.getRandomValues`，无 `Math.random()`
- [ ] **B2 密钥单源**：HMAC 密钥仅出现在 `server/lib/hmac.js` 与 `web/js/hmac-spec.js`，业务代码无硬编码字面量
- [ ] **B3 输入校验**：外部输入先判空/`isNaN` 再使用，无裸 `req.headers[...]` 直接进算法

### 算法与数值（红线 7、8、9）
- [ ] **B4 交叉验证**：新增/修改的历法·命理数值，有≥2 库交叉验证证据，差异已说明（流派 vs bug）
- [ ] **B5 边界覆盖**：闰月/跨年/晚子时/节气交界月建有抽样，无遗漏
- [ ] **B6 无重复实现**：相同算法已抽公共模块，调用方引用而非重写

### 前端（红线 10、11、12）
- [ ] **B7 令牌化**：新增颜色/字号全部用 `variables.css` 令牌，无散落 `#xxxxxx` / 写死 `px`
- [ ] **B8 异常不吞**：`fetch`/`await` 均有 `.catch`，无空 `catch(e){}`
- [ ] **B9 模块规范**：共享规范在 `web/js/*-spec.js`，业务组件 `import` 引用，无内联重复常量

### 可维护性（红线 1、2、3、13、14）
- [ ] **B10 可还原**：有备份、有还原说明；紧急时可一键回退
- [ ] **B11 聚焦**：提交只做一件事，diff 干净，无无关改动
- [ ] **B12 注释到位**：非显然逻辑（如晚子时换日、命宫流派差异）有注释说明"为什么"

## C. 合并标准

- 全部 A、B 项勾选 ✅ → 可合并
- 任一 B 项未过 → 打回，注明原因
- 安全类（B1–B3）零容忍，一票否决
