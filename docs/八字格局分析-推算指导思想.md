## 二、推算指导思想

### 2.1 核心哲学

```
月令提纲 → 日主强弱 → 格局判定 → 喜用神推导 → 岁运指引
```

**第一原则（《子平真诠》卷三）**：
> "八字用神，专求月令。以日干配月令地支，而生克不同，格局分焉。"

月令地支的本气十神决定格局大方向。日主强弱决定扶抑方向。

**第二原则（《滴天髓》上篇）**：
> "阳干从气不从势，阴干从势无情义。"

日主为阴干（乙丁己辛癸）时，从格条件可从宽；日主为阳干（甲丙戊庚壬）时，从格需严格判据。

### 2.2 格局判定流程

```
1. 日主强弱评估 (_assessDayMasterStrength)
   ├─ 得令（月令藏干十神系数 ×3）
   ├─ 得地（通根）— 年/日/时支藏干权重扫描
   └─ 得助（天干印比）— 月/时干紧贴权重 0.8
        │
2. 日主强度分类
   ├─ 极旺 / 偏旺 → 扶抑法·克泄耗
   ├─ 中和 → 扶抑法·月令为先
   ├─ 偏弱 / 极弱 → 扶抑法·生扶
   └─ 极弱 + 无根 + 异党 > 85% → 进从格候选
        │
3. 月令提纲定位 (_dinggeGetSiLing)
   ├─ 取月令本气十神
   └─ 透干验证（年/月/时干是否有同五行）
        │
4. 格局命名 (_dinggeAnalyzeSizhu)
   └─ 月令本气十神 + 透干确认 → 格局名称
```

### 2.3 从格判定（双路径）

| 路径 | 函数 | 状态 |
|------|------|------|
| ~~MD 新管道~~ | `_congCheck_md()` (core/patterns.js) | **已删除**（2026-06-26，推算错误） |
| **旧管道（当前）** | `determineCongGe()` (core/bazi.js) | **活跃**，基于 `_computeCongGeData()` 计算从势力量比 |

旧管道从格判定逻辑：

```
日主五行分数占比 < 15%  → 从格候选
         │
生扶力量 < 15% / 克泄耗 > 85%  → 从格成立
         │
从格类型由全局最旺十神决定
  ├─ 财星最旺 → 从财格
  ├─ 官杀最旺 → 从杀格
  └─ 食伤最旺 → 从儿格
```

**假从判定**：天干见印比或藏干隐藏印比 → 假从格。详见 `_computeCongGeData()` 中的 `hasTianGanBiJie` / `hasHiddenYinBi` 标志。

## 三、数据来源

### 3.1 引擎层（core/engine/sxwnl-bundle.js）

| 数据 | 函数 | 说明 |
|------|------|------|
| 四柱干支 | `mingLiBaZi()` | 年/月/日/时柱的天干地支索引 (b1-b4) |
| 藏干数据 | `_DG_GAN[]`, `_DG_BENQI[]`, `_DG_ZHONGQI[]`, `_DG_YUQI[]` | 十二地支藏干映射表（本气/中气/余气） |
| 十神关系 | `Lunar.sshen()` / `_localSShen()` | 天干对日主的十神类型 |
| 大运数据 | `dayunjl()` | 起运年龄和十年大运排盘 |

### 3.2 计算层（core/bazi.js）

| 卡片 | 核心函数 | 数据来源 |
|------|---------|---------|
| **八字格局** | `determineBaziPattern()` | `_assessDayMasterStrength()` → 日主强弱等级 + 百分比 |
| | `_dinggeGetSiLing()` | `_DG_BENQI[monthBranch]` → 月令本气十神 |
| | `_dinggeCheckTouGan()` | 天干扫描 → 透干确认 |
| | `_dinggeAnalyzeSizhu()` | 四柱配合分析 |
| | `_qiSShen()` / `_localSShen()` | 十神名映射 |
| **八字喜用** | `determineXiyongshen()` | 基于格局类型 + 日主强弱 → 扶抑/顺势选择 |
| | `_getXiyongWx()` | 将十神用神翻译为五行用神 |
| | `_renderTiaoHou()` | **穷通宝鉴** 月令调候表 |
| | `_renderLiuTong()` | 命局五行生克→通关用神 |
| | `_pillarRelations()` | 四柱刑冲合害检测 |
| **八字从格** | `determineCongGe()` | `_computeCongGeData()` → 生助力量百分比 |
| | `_computeCongGeData()` | 天干印比检测 + 藏干印比检测 + 异党百分比 |
| | 五条件表 | 日主无根 / 天干无印比 / 异党≥70% / 月令不助 / 无印通关 |

### 3.3 五行力量层（core/wuxing.js）

| 层次 | 权重 | 内容 |
|------|------|------|
| 月令 | ×3 | 月支藏干十神系数 |
| 通根 | ×1.2（年/日/时） | 非月支藏干同五行根 |
| 天干 | ×0.8（紧贴） | 月/时干十神系数 |
| 生克 | ±0.3 | 五行相生相克调整 |
| 合化 | ±0.2 | 天干五合、地支六合 |
| 纳音 | ±0.1 | 纳音五行补正 |

日主占比 = 印比总分 / 全五行总分 × 100%。

### 3.4 卡片生成层（server/routes/bazi.js）

| 步骤 | 函数 | 说明 |
|------|------|------|
| 1 | `mingLiBaZi()` | 引擎生成原始 bzinfo HTML（含全部分析文字） |
| 2 | `renderBaziTable()` | 生成专业排盘表格 |
| 3 | `_splitBzinfoToCards()` | 扫描 HTML 中的 `bt-card` / `data-card-id` 标记，拆分为结构化卡片数组 |

**注意**：卡片文字内容来自引擎的 `mingLiBaZi()` 输出，而非独立的模板。修改卡片文字需要修改引擎中的对应函数（如 `_renderNianZhu` / `_renderYueZhu` / `_renderRiZhu` / `_renderShiZhu`）。

- `_baziAnalysis_md()` — MD 规范格局分析
- `_congCheck_md()` — MD 五条件从格检测 
- `_checkHuaGe_md()` — 化气格检测

**删除原因**：推算结果与古籍命例不符，置信度低（Analysis 2 仅 57%），用神方向常得出错误结论。

## 六、Agent 操作指南

### 修改卡片文字

1. 定位引擎生成函数（`core/bazi.js` 对应行号）
2. 修改 HTML 模板字符串（注意繁体/简体一致性）
3. 重启 server
4. 调用 `POST /api/v1/bazi` 验证

### 修改格局判定逻辑

1. 修改 `_assessDayMasterStrength()` 的评分系数
2. 修改 `determineCongGe()` 的从格阈值
3. 运行 `npm test` 验证回归
4. 对比 5+ 已知命例确保无退化

### 添加新卡片

1. 在引擎的 `mingLiBaZi()` 调用链中添加 `bt-card` / `data-card-id` 标记
2. `_splitBzinfoToCards()` 会自动识别并拆分
3. 无需修改客户端渲染逻辑
