- 用户"继续" → 专题带教② HMAC 安全。审计 `server/lib/hmac.js`+`middleware/auth.js`+`web/js/hmac-spec.js`+`web/js/api.js`。
- **真实安全缺陷（Finding A，已修）**：`hmac.js:51` 与 `auth.js:34` 用 `!==` 比较签名，**非时序安全**（短路比较，可被逐字节时序爆破）。因客户端`hmac-spec.js`明文持有密钥（=任意用户即攻击者），风险真实。新增 `constantTimeEqual`（Buffer+`crypto.timingSafeEqual`，长度不等直接 false 不抛）并用于 `verify()` 与 `auth.js`。
- **架构事实（Finding B，写清威胁模型）**：客户端明文持有密钥 → 这层是"身份识别/防扫"，非"保密/防持有者伪造"。建议部署用 `HMAC_SECRET` 环境变量覆盖默认密钥。
- **设计权衡（Finding C/D，仅文档化，不动）**：①8 hex(4字节前缀) 是项目既有契约(Android/keygen/worker 共用)，单改会全线失效，配 nonce一次性+5分钟窗可接受；②`nonceCache` 内存 Map 重启清空可短窗重放、无 TTL 清扫——本地应用风险低，上云再加固。
- **正面范例（Finding E）**：nonce 用 `crypto.randomBytes`/`getRandomValues`（此前抽库已根除 `Math.random`）保留，作团队随机源规范样板。
